# Product descriptions and blank printing

Each Products and Price row has an optional **Description** (plain, multiline text) next to the Item name. Expand a row to edit it. It is saved and printed with that product. The Item lookup no longer supplies or replaces this wording; changing or clearing an Item retains the description so the user can review it deliberately. Existing saved descriptions, including those previously copied from Item masters, are retained. Blank descriptions stay blank. Submitted contracts retain native read-only protection; amendments copy the recorded description.

HTML-like descriptions use Frappe’s normal sanitization. Printing decodes one entity layer for angle-containing wording (including escaped inequalities), then escapes the complete result as plain text. Standalone literal entity text remains unchanged; printing never rewrites stored descriptions.

No data patch is needed: `PZ Contract Item.description` already exists as Small Text. A normal app migration syncs its editable metadata for new and saved draft forms without rewriting rows. No production migration was run for this change.

**Print Blank Template** opens a source-contract picker from new, saved draft and submitted forms. Choose a saved contract whose seller details, terms and Incoterm match the intended template, then choose **Preview Blank Template**. Saved forms preselect themselves; new forms do not need to be saved. The server reloads the selected source and requires native document Read/Print permissions, including native draft/cancelled printing settings. Unsaved form values are never used.

The worksheet prefills the seller's saved legal/contact details, signatory and position, the existing private company stamp (when present), and the exact clauses printed for the selected source, together with its saved Incoterm. Historical snapshots and custom wording are retained, including the source's payment split, readiness and loading/export obligations. No Incoterm variant or new legal wording is generated. Review copied terms for transaction-specific wording before printing; custom legal text is copied verbatim rather than automatically redacted. Missing optional stamp assets leave blank stamp space.

Buyer, products, quantities, prices, amounts, dates, contract reference, currency, named place and bank/payment-instruction fields stay blank for manual completion. Only an explicit seller/legal/branding whitelist reaches the blank renderer; it never receives the full source document or populated-print context. The worksheet has a commercial page, terms pages (five clauses per page) and a signature page. Use its Print button or the browser print command to print or save as PDF. It creates or modifies no contract, Sales Order, stock or accounting entries. Ordinary populated print routing and terms snapshots remain unchanged.

Both features require the reviewed app code and synchronized DocType metadata on the site; merging a PR does not deploy it. The reported readonly **ERP description** field and missing toolbar button were confirmed on an older deployed app revision, so the site owner must deploy the merged revision before these controls appear.

## Editable Word downloads

On a saved contract, choose **Download Word (.docx)** in the toolbar. Save any edits first; the download always uses the persisted contract, including its saved print-as-draft/cancelled marker, product descriptions, commercial details, exact terms, Incoterm, seller/signatory/title and existing private stamp. A new contract must be saved before downloading its populated Word file. The browser downloads an actual Office Open XML `.docx` containing editable paragraphs and tables, with embedded logo/stamp images; it is not a PDF or HTML file renamed to Word.

For a worksheet, choose **Download Blank Word (.docx)**, select the saved seller/terms/Incoterm source, then **Download Word (.docx)**. This uses the same source picker, permissions and blanking rules as Print Blank Template. Buyer/product/pricing/bank/date/reference fields remain blank. Copied legal wording remains verbatim, so review any transaction-specific custom clauses.

Both downloads enforce native source-document Read/Print access and draft/cancelled print settings. Neither saves or uploads an export, creates a File record, modifies the source, or creates stock/accounting records. The stamp is embedded from the exact existing `sites/<site>/private/files/petrol_zone_stamp.png` loader without changing its permissions or creating a public image URL. Ordinary PDF/HTML printing is unchanged.

Word page layout uses A4, native headings/tables, repeatable product-table headers and running contract/status markers so long tables can continue across pages. Word processors may paginate differently from the PDF layout; the text and images remain editable. Historical schedules, appendices and saved clause versions follow the same canonical print template as populated PDF printing. The app declares `python-docx` as a Python dependency; an existing bench update must install the updated project dependencies before using Word downloads. No production installation or deployment was performed for this feature.
