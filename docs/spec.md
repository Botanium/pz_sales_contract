# Implementation specification

User-authorized scope: implement, test and publish this dedicated app in public Botanium/pz_sales_contract. Production installation/deployment, sending contracts and signing contracts remain excluded.

- Sales team selects ERPNext Customer, Item, a per-line Bitumen Grade master and linked details; quantity/UOM/rate/currency/discount/item-only totals and Incoterm plus named place are captured. Packaging is derived server-side from verified Item IDs for the print and is not an entry field. Contract line Grade maps to Sales Order Item `custom_bitumen_grade`; legacy free-text Grade snapshots remain intact for existing contracts. New contracts omit delivery date and contract tax details; they create a linked Draft Sales Order for manual delivery-date/tax entry and submission. Legacy contracts retain their stored values and prior Sales Order behavior.
- New contract families pin the user-approved v2 clause list and print version in hidden fields. Their print uses the completed deal details and payment instructions, omits the Commercial Schedule, product-specification appendix, Approval / Collection Record and fixed 24-business-hour text, and retains signature lines. The 30% advance and 70% balance remain calculated on discounted goods only; any applicable taxes are separately recorded on the linked Sales Order or invoice and are outside that Contract Amount. V2 adds no payment deadline, penalty, charge, delivery default or legal venue.
- Amendments retain their source clause snapshot and print version. Pre-version and pre-snapshot records keep the legacy print layout; records without a snapshot use immutable `terms_versions/v1.json`, guarded by its pinned SHA-256. Existing schedule/specification schema and historical values remain stored for these legacy records. The optional specification-reference value remains hidden from entry and print.
- Attractive branded print/PDF with supplied logo, clean pagination, versioned terms and signatures.
- Each contract has a visible operator-controlled `Print as Draft` checkbox, default unchecked for new and existing rows after schema migration. When checked, all native HTML/PDF routes print only the word DRAFT as the draft mark; when unchecked, payment/customer history and receipt evidence do not add a draft mark. Cancelled contracts remain marked CANCELLED. The checkbox is editable after submission and is not copied to amendments.
- Advance receipt evidence does not gate contract save, submission or printing. Restricted PZ Customer History continues to validate identified pre-app finance history independently; payment entries, ledgers, reconciliation safeguards and 30% / 70% contract amounts remain intact.
- Handle cancellations, amendments, concurrency, duplicate allocations and company/currency isolation. Preserve the restricted pre-app finance-history workflow without using it to choose the current contract print marker.
- Feature branch and draft PR; preserve unrelated repos/work; public staged diff has no credentials, real customer/payment records, dumps or Library metadata.
- Native v16 integration in a disposable site with synthetic fixtures; permissions, checkbox defaults, checked/unchecked paid/unpaid new and existing customers across native save/submit/HTML/PDF paths, cancellation, legacy defaults, arithmetic and print tests. Verify exact remote commit and CI.
- Company-specific Incoterm choices always include EXW/FOB/CIF, allow only additional native Incoterm masters configured per seller Company, and do not auto-select a term.
- New entry-policy contracts use fixed USD, a server-resolved internal USD selling price list and stored native accounting conversion. Exact verified Item IDs supply packaging for new or changed lines across contract families; unknown Items retain no inferred packaging, while unchanged legacy lines retain their saved packaging snapshots. A searchable PZ Contract Location supplies the named-place snapshot. Existing records retain their currency, rate, and place snapshots. See [entry policy](usd-packaging-location-entry.md) for configuration, permissions and verification limits. This follow-up is prepared locally; its publication and deployment require separate authorization.
- Approved follow-up policy: the contract uses discounted item amounts only; delivery date and applicable taxes are completed on the linked Sales Order before the user manually submits it. Keep the linked order Draft until that user action. Do not auto-submit or invent a delivery date.

The readable master SHA and transcription provenance are in master-provenance.md. README records implementation decisions and explicit limitations.

## Approved access and merge follow-up (2026-10-01)

- Use dedicated `PZ Sales Contract User` and `PZ Sales Contract Manager` roles. Generic Sales User, Sales Manager, Accounts Manager and System Manager roles must not expose contracts to incidental existing users. Administrator retains native full access. App roles do not grant native accounting, payment, finance-history or registry access, and installation/migration must not assign user roles.
- Review the complete PR and merge through the normal GitHub flow after independent review and exact-head checks pass. Production installation and the explicitly approved user-role assignments are a separate deployment workflow; never create production contracts or transactions for validation.

## Manual print marker follow-up (2026-10-06)

- Payment evidence no longer determines a current contract's print state or blocks its save, submission or print routes. The saved `print_as_draft` checkbox defaults off and is the only source of the DRAFT mark; cancelled status takes precedence. Amendments default off. Existing receipt, allocation and finance-history records are preserved.
- Remove the first-advance warning banner, receipt-status line and Desk advance-evidence dialog. Keep the agreed 30% / 70% figures and native accounting safeguards.
